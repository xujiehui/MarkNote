## 实际技术调整

- 旧 `marknote` 库原位保留为访客库，只增加事务性表升级；没有把可能混合归属的旧数据复制给登录账号。账号空间使用稳定的编码 provider/user ID，而非引入 UUID catalog 与全量影子迁移。选择减少了旧数据复制和误认领；已有旧数据不一定能自动判断真正归属，需通过明确导入创建副本。
- 草稿按独立编辑器保存，避免同毫秒、同笔记的多个标签页互相覆盖。永久删除或远端更新前，未提交的独立草稿会先保全成新恢复副本；原始待修复草稿不会被健康草稿恢复掩盖。
- 历史存入 IndexedDB，以附件引用和每笔记字节去重保存不可变媒体。恢复创建当前附件新 ID，替换图片也创建新 ID。历史专用附件不自动进入云同步；历史只保存在本地及备份中。
- 孤立旧历史迁移为新 ID 的“历史恢复”笔记，迁移先保全同源草稿及附件。缺失字节时事务回滚并保留原始 localStorage，不写入会阻断健康备份的孤立历史。
- 恢复只支持副本与显式跳过，不开放覆盖既有笔记。应急恢复文件另存原始修复来源与安全可导入副本，体积仍受正常导入上限约束。
- 本轮不清理无确认的旧原始历史源，也不自动执行生产 SQL。后端 V2 禁止旧客户端直接写入；回滚须保留新协议数据与本地未确认变更。
